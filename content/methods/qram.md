## How it works

A QRAM implements the map Σ_i α_i |i⟩|0⟩ → Σ_i α_i |i⟩|x_i⟩ for N stored classical values x_i. Bucket-brigade proposals route an address through a tree with O(N) components and O(log N) ideal query depth. Some quantum linear-algebra and machine-learning speedups assume this kind of coherent access. Logarithmic *depth* is not logarithmic *hardware footprint* or proof of an end-to-end gain; the accounting depends on the architecture and the number of queries [1].

## Preconditions

For a QRAM-based speedup on classical data to be real:

1. Count the N memory values, routing components, controller, ancillas and fault-tolerance costs. A depth estimate alone omits space and power.
2. State whether the data arrive preloaded, are generated by a circuit, or must be written. Loading N arbitrary classical values costs at least Ω(N) once; repeated queries can amortise that initial cost.
3. Compare against a classical system with a stated hardware budget and the same task, accuracy and number of queries. The hardware opportunity cost in [1] is an argument under architecture assumptions, not an unconditional complexity lower bound for every QRAM-dependent algorithm.

## Known limits

- **Storage and readout.** Holevo limits complete recovery of classical information from a transmitted quantum state under its assumptions. QRAM ordinarily stores classical values in a separate memory and provides coherent *access* to them; Holevo alone does not rule out a faster downstream computation. See the [classical-data primitives page](../problems/sorting-fft-storage.html) for the distinction between full recovery and selected-bit retrieval.
- **Physical footprint and comparator.** In a bucket-brigade query, a basis-state address follows one route through the tree. This does not imply every cell is directly touched on that route. A scalable implementation still needs O(N) stored values and routing resources. Jaques and Rattew argue that the control or error-corrected hardware for active QRAM could, in many applications, be repurposed for an extremely parallel classical computation; their detailed asymptotic result concerns quantum linear algebra with architectural qualifications [1]. They also conclude that existing passive proposals do not yet establish a cheap, scalable alternative, while explicitly leaving room for future designs [1].
- **Alternative architectures.** Cesa, Bernien and Pichler propose a resource-state QRAM with offline state preparation and discuss error correction and a neutral-atom implementation [2]. The proposal changes the latency and reliability tradeoff; it is neither a demonstrated industrial QRAM nor a refutation of every opportunity-cost comparison. Total physical resources and matched classical throughput still need to be measured.
- **Algorithm-dependent limits.** Sampling-access dequantization applies to specified low-rank linear-algebra and recommendation tasks [3]; it does not dequantize all QRAM algorithms. A separate [streaming-data problem](../problems/streaming-classical-data-memory.html) has a proved quantum *space* separation on constructed inputs [4]. That result uses a different access model and does not validate QRAM-based time advantages.

## Verdict

Surviving as an access-method research question, with no documented practical advantage for a QRAM-dependent application in the cited work. Loading arbitrary classical data and building the memory have unavoidable costs; active-QRAM opportunity cost defeats *many* proposed linear-algebra speedups under the comparator of [1]. It is too strong to call this a universal no-go for all QRAM uses. A positive application case needs a concrete workload, a buildable memory design, the cost of loading and repeated queries, and a time/area/energy comparison against the best classical architecture with the same output and accuracy.
